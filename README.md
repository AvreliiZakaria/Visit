# Вердикт (Verdict)

Суд присяжных из незнакомцев для бытовых споров. Двое записывают по 60 секунд аргументов,
дело уходит случайным присяжным, при кворуме приходит вердикт с процентами и комментариями.
Проигравший получает бейдж на 30 дней.

Это не макет. Здесь есть сервер, база, запись и раздача аудио, движок вердиктов,
модерация с интерфейсом разбора, платежи и удаление данных.

---

## Быстрый старт

```bash
git clone https://github.com/AvreliiZakaria/Visit.git
cd Visit
npm install
cp .env.example .env

# сгенерируй секрет и вставь его в JWT_SECRET внутри .env
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"

npm start
```

Открой `http://localhost:3000`.

**Чтобы пройти полный круг локально**, поставь в `.env` строку `JURY_MIN_QUORUM=2`
и `ADMIN_EMAIL=твоя@почта`. Дальше:

1. Зарегистрируйся, создай спор, запиши 60 секунд.
2. Скопируй ссылку-приглашение, открой её в приватном окне, зарегистрируй второй аккаунт, запиши ответ.
3. Открой третий и четвёртый аккаунты, зайди в «Зал жюри», прослушай обе записи целиком, проголосуй.
4. Как только голосов станет два, планировщик вынесет вердикт. Первое окно покажет проценты без перезагрузки.

Микрофон в браузере работает только на `localhost` или по HTTPS. По голому IP запись не запустится.

## Как это работает по шагам

1. **Создание дела.** `POST /api/disputes` возвращает дело и ссылку-приглашение,
   затем `POST /api/disputes/:id/sides` с файлом записи.
2. **Расшифровка и модерация.** После загрузки сервер отправляет запись на распознавание,
   прогоняет текст через `moderation.scan`, вырезает найденные телефоны, адреса и почты.
   Заблокированная запись создаёт задачу в `admin.html`, дело в фид не попадает.
3. **Вторая сторона.** По ссылке `join.html?t=<token>` человек регистрируется, принимает дело
   и записывает свои 60 секунд. Только после этого дело открывается для жюри.
4. **Зал жюри.** `GET /api/jury/next` выдаёт дело и фиксирует время выдачи.
   Порядок сторон перемешивается детерминированно от пары «дело плюс присяжный»,
   поэтому при перезагрузке не меняется.
5. **Голос.** `POST /api/jury/:id/vote` проверяет на сервере пять вещей: дело выдавалось
   именно этому присяжному, прошло минимальное время, прослушивание не ниже порога,
   заявленное прослушивание физически укладывается в прошедшее время, голоса от этого
   пользователя и устройства в деле ещё нет.
6. **Вердикт.** Планировщик раз в 15 секунд закрывает дела: собран целевой размер жюри
   или вышел дедлайн при достигнутом минимуме. Ниже минимума вердикта нет,
   а платежи за срочность возвращаются на внутренний счёт.

## Правила, зашитые в код, а не в маркетинг

- **Голоса живые.** В `server/lib/court.js` нет функции, создающей голос без присяжного,
  и в `seed.js` тоже. Накрутка ботами это не «трюк для холодного старта», а причина,
  по которой приложение снимают из магазина и перестают верить всем вердиктам сразу.
- **Счёт скрыт до вердикта.** Проценты не появляются ни в одном ответе API, пока нет записи
  в таблице `verdicts`. Присяжный после голоса получает только подтверждение.
- **Голос только после прослушивания.** Клиент считает реально проигранное время,
  а не позицию ползунка: перемотка вперёд не помогает. Решение всё равно за сервером.
- **Дело не публикуется без второй стороны.** Односторонняя публикация возможна только
  после истечения срока на ответ и с видимой пометкой для присяжных.
- **Контент только по согласию.** `GET /api/content/reels` отдаёт дела с галочкой согласия
  и только после вердикта. Аудиофайлы через этот маршрут не уходят никогда.
- **Удаление работает.** `DELETE /api/auth/me` стирает записи, голоса и историю сразу.
  Из списка беты тоже можно удалиться, до всякой регистрации.

## Режимы работы

| Настройка | Пусто | Задано |
|---|---|---|
| `OPENAI_API_KEY` | Расшифровки нет. При `MODERATION_STRICT=false` дела публикуются, при `true` уходят на ручную проверку | Whisper распознаёт речь, модерация работает по тексту |
| `STRIPE_SECRET_KEY` | Песочница: покупка подтверждается локально, деньги не двигаются | Настоящий Stripe Checkout, права выдаются только из вебхука |
| `ADMIN_EMAIL` | Администратора нет, `admin.html` недоступен | Указанный адрес получает роль admin при регистрации |

Вебхук для продакшена: `POST /api/payments/webhook`, событие `checkout.session.completed`.
В мобильных приложениях схема та же: покупка проверяется на сервере через IAP или RevenueCat,
а не в самом приложении.

## Перед продакшеном

1. **HTTPS обязателен.** Без него не работает микрофон и не защищена кука сессии.
   Поставь Caddy или nginx перед приложением.
2. **Свой `JWT_SECRET`.** В режиме production сервер не запустится без него, и это правильно.
3. **Бэкапы.** Копируй `data/verdict.sqlite` и папку `uploads` вместе: по отдельности они бесполезны.
4. **Юридические документы.** Политика конфиденциальности и условия использования нужны
   до первого живого пользователя, а не после.
5. **Живая модерация.** Пока людей мало, `admin.html` надо открывать каждый день.
   Автоматика ловит личные данные, но не понимает контекст.
6. **S3 вместо диска**, когда инстансов станет больше одного.

## Чего здесь ещё нет

Честный список, чтобы не было сюрпризов:

- **Письма.** Напоминания второй стороне считаются в базе, но наружу не уходят: нужен SMTP.
- **Пуш-уведомления.** Для веба Web Push, для мобилок FCM и APNs.
- **Мобильные приложения.** Здесь веб. Нативные оболочки используют то же API без изменений.
- **Восстановление пароля.** Забыл пароль, потерял аккаунт. Делается вместе с письмами.
- **Тесты.** Ни одного. Первое, что стоит написать: правила голосования из `court.js`.
- **Проверка изображений и видео.** В продукте их нет, только аудио.
