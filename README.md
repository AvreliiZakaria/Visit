# Вердикт (Verdict)

Спор с партнёром или другом решает суд присяжных из ста незнакомцев.
Оба записывают по 60 секунд аргументов, жюри слушает обе стороны и голосует,
вердикт приходит с процентами, бейджем проигравшему и лучшими комментариями.

Это не макет: есть база, аккаунты, загрузка аудио, распределение дел по присяжным,
серверная проверка «слушал или нет», подсчёт вердикта по кворуму, модерация, платежи и аналитика.

---

## Быстрый старт

```bash
cd server
cp .env.example .env      # смени JWT_SECRET и ADMIN_TOKEN
npm install
npm run seed              # добавит дела, чтобы зал жюри не был пустым
npm start
```

Открой `http://localhost:8080`. Сервер сам раздаёт фронтенд из корня репозитория.

Через Docker:

```bash
docker compose up --build
```

## Что реально работает

**Аккаунты.** Анонимные, без почты и пароля. Device id превращается в хеш и работает как правило
«один голос с одного устройства». Есть обезличивание аккаунта по запросу.

**Запись.** Настоящий микрофон через MediaRecorder, живая волна через AnalyserNode, обрыв на 60 секундах.
Файл летит на сервер, лежит на диске, отдаётся только сторонам дела и присяжным с живым назначением.

**Распределение дел.** Присяжный получает одно дело за раз. Свои дела не выдаются, повторно тоже.
Порядок сторон случайно перемешивается, чтобы первый голос не выигрывал автоматически.
Срочные дела идут вперёд, дальше те, где меньше голосов и которые ждут дольше.

**Проверка голоса на сервере.** Клиент говорит, сколько прослушал, но решает сервер:
меньше 80% по любой стороне — отказ, быстрее 15 секунд после выдачи — отказ,
второй голос с того же устройства — отказ. Счёт в ответе не приходит вообще.

**Вердикт.** Планировщик раз в 15 секунд закрывает дела по кворуму или по таймауту,
считает проценты, выдаёт проигравшему бейдж на 30 дней, обновляет счёт побед.

**Модерация.** Тема и транскрипт проходят автопроверку на телефоны, адреса, документы, угрозы,
упоминания несовершеннолетних и ссылки на профили третьих лиц. Спорное уходит на ручной разбор,
запрещённое блокируется. Три жалобы снимают дело из фида автоматически. Есть админские ручки и баны.

**Деньги.** Тарифы, применение покупки, история платежей. Провайдер намеренно заглушка:
в мобильном приложении это покупки App Store и Google Play, в вебе Stripe.
Логика применения тарифа готова, вебхуку остаётся её дёрнуть.

**Аналитика.** События пишутся в базу, `GET /api/funnel` показывает воронку:
регистрации, созданные дела, доля дошедших до жюри, голоса, платежи, выручка.

## Правила, зашитые в код, а не в маркетинг

- Голоса живые. Ботов нет даже на старте: `npm run seed` создаёт дела, но ни одного голоса.
- Пока кворума нет, время вердикта не обещается. Показывается честный счётчик.
- Счёт скрыт до вердикта, иначе включается стадный эффект.
- Без записи второй стороны дело не публикуется. Односторонний вариант возможен только через сутки и с пометкой.
- Оплата влияет на скорость и размер жюри, но никогда на результат.
- Спор попадает в публичный контент только по явной галочке. Оригинальный голос не публикуется.

## Чего здесь нет

Транскрибация аудио (нужен Whisper или аналог, поле `transcript` уже есть и участвует в модерации),
пуш-уведомления, настоящий платёжный провайдер, S3 вместо диска, PostgreSQL вместо SQLite,
очередь задач вместо `setInterval`. Всё это меняется точечно: границы уже прочерчены.

## Настройки

Всё через переменные окружения, см. `server/.env.example`:
размер жюри, минимальный кворум, сроки бесплатного и срочного суда,
порог прослушивания, минимальное время на размышление, секреты.

## Публикация

GitHub Pages покажет только статику: лендинг и `app.html`. Суду нужен сервер,
поэтому `court.html` и `join.html` работают там, где запущен Node: Docker, Render, Fly, VPS.
