# Вердикт (Verdict)

Суд присяжных из незнакомцев для бытовых споров. Двое записывают по 60 секунд аргументов,
дело уходит случайным присяжным, при кворуме приходит вердикт с процентами и комментариями.
Проигравший получает бейдж на 30 дней.

Это не макет. Здесь есть сервер, база, запись и раздача аудио, движок вердиктов,
модерация, платежи и удаление данных.

---

## Быстрый старт

```bash
git clone https://github.com/AvreliiZakaria/Visit.git
cd Visit
npm install
cp .env.example .env
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"   # вставь в JWT_SECRET
npm start
```

Открой `http://localhost:3000`. Лендинг работает сразу, приложение потребует регистрации.

Чтобы пройти полный круг, нужны два аккаунта: заведи второй в приватном окне,
создай спор с первого, открой ссылку-приглашение во втором. Дальше нужны присяжные:
минимальный кворум задаётся в `.env` через `JURY_MIN_QUORUM`, для локальной проверки поставь `2`.

## Как это работает по шагам

1. **Создание дела.** `POST /api/disputes` возвращает дело и токен-приглашение.
   Дальше `POST /api/disputes/:id/sides` с файлом записи.
2. **Транскрибация и модерация.** После загрузки сервер отправляет запись на распознавание,
   прогоняет текст через `moderation.scan`, вырезает найденные персональные данные.
   Заблокированная запись создаёт задачу модератору, дело в фид не попадает.
3. **Вторая сторона.** По ссылке `join.html?t=<token>` человек регистрируется,
   принимает дело и записывает свои 60 секунд. Только после этого дело открывается для жюри.
4. **Зал жюри.** `GET /api/jury/next` выдаёт дело и создаёт запись о выдаче со временем.
   Порядок сторон перемешивается детерминированно, чтобы при перезагрузке не менялся.
5. **Голос.** `POST /api/jury/:id/vote` проверяет на сервере четыре вещи: прошло ли
   минимальное время с выдачи, заявленное прослушивание не меньше порога, заявленное
   прослушивание физически укладывается в прошедшее время, и голоса от этого человека
   и этого устройства в деле ещё нет.
6. **Вердикт.** Планировщик раз в 15 секунд закрывает дела: собран целевой размер жюри
   или вышел дедлайн при достигнутом минимуме. Ниже минимума вердикта нет, а платежи
   за срочность возвращаются на внутренний счёт.

## Правила, зашитые в код, а не в маркетинг

- **Голоса живые.** В `server/lib/court.js` нет функции, создающей голос без присяжного.
  Накрутка ботами это не «трюк для холодного старта», а причина, по которой приложение
  снимают из магазина и перестают верить всем вердиктам сразу.
- **Счёт скрыт до вердикта.** Проценты не появляются ни в одном ответе API,
  пока нет записи в `verdicts`. Присяжный после голоса получает только подтверждение.
- **Голос только после прослушивания.** Проверка серверная. Клиент считает реально
  проигранное время, а не позицию ползунка: перемотка не помогает.
- **Дело не публикуется без второй стороны.** Односторонняя публикация возможна
  только после истечения срока на ответ и с видимой пометкой.
- **Контент только по согласию.** Выгрузка для видео `GET /api/content/reels` отдаёт
  дела с `consent_content = 1` и никогда не отдаёт аудиофайлы, только текст.
- **Удаление работает.** `DELETE /api/auth/me` стирает записи, голоса и историю.

## Режимы работы

| Настройка | Пусто | Задано |
|---|---|---|
| `OPENAI_API_KEY` | Транскрипта нет. При `MODERATION_STRICT=false` дела публикуются, при `true` уходят на ручную проверку | Whisper распознаёт речь, модерация работает по тексту |
| `STRIPE_SECRET_KEY` | Песочница: покупка подтверждается локально, деньги не двигаются | Настоящий Stripe Checkout, права выдаются только из вебхука |
| `ADMIN_EMAIL` | Администратора нет, очередь модерации недоступна | Указанный адрес получает роль admin при регистрации |

Вебхук для продакшена: `POST /api/payments/webhook`, событие `checkout.session.completed`.
Для мобильных приложений схема та же: покупка проверяется на сервере через IAP или RevenueCat,
а не в приложении.

## Чего здесь ещё нет

Честный список, чтобы не было сюрпризов:

- **Письма.** Напоминания второй стороне считаются в базе, но наружу не уходят:
  нужен SMTP или сервис рассылок.
- **Пуш-уведомления.** Для веба нужен Web Push, для мобилок FCM и APNs.
- **Мобильные приложения.** Здесь веб. Нативные оболочки на Flutter или React Native
  используют то же API без изменений.
- **Хранилище файлов.** Аудио лежит на диске сервера. Для нескольких инстансов нужен S3.
- **Автоматическая проверка изображений и видео.** Их пока нет в продукте, только аудио.
- **Тесты.** Ни одного. Первое, что стоит написать: правила голосования в `court.js`.
